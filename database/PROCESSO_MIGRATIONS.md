# Processo de Migrations (Database Evolution)

Este diretório implementa a **REGRA DATABASE EVOLUTION** (ADR-006).

## Princípio

```text
Dump SQL congelado  = fonte de verdade do LEGADO (somente leitura)
MD / MAP            = arquitetura DESEJADA
SQL (migrations)    = materialização da EVOLUÇÃO
```

## Estrutura

```text
database/
├── dump/
│   └── Dump20260618.sql        (BASELINE — NUNCA alterar)
├── migrations/
│   ├── proposed/               (KILO gera aqui; aguarda aprovação)
│   └── approved/               (somente após aprovação)
└── seeds/
```

## Fluxo KILO

```text
KILO AUDIT
   │
   ├─ Comparar: Dump × MDs × MAPs × FRONTs
   │
   ├─ Existe no Dump?  ── SIM ──> Validar e USAR
   │
   └─ Não existe?      ── NÃO ─> Gerar PROPOSTA (não criar)
                              │
                              └─> migrations/proposed/MD-XXX-*.sql
                                  STATUS: PROPOSED / REQUIRE APPROVAL
```

## Marcação obrigatória de SQL gerado

```sql
-- GENERATED BY KILO ENGINE
-- STATUS: PROPOSED
-- REQUIRE APPROVAL
```

## O que o KILO NUNCA deve fazer

```text
❌ Alterar o dump original
❌ Criar tabela porque viu um componente React
❌ Criar banco baseado em imagem
❌ Criar SP sem contrato
❌ Criar coluna sem MD/MAP
```

## Exemplo (Portal Runtime)

`PortalRuntimeContract` existe (frontend). `sp_portal_runtime` **não existe** no dump.
Correto: ao chegar na integração real, o KILO cruza FRONT-003 + MAP CORE PLATFORM + MD Database e
gera `migrations/proposed/MD-PORTAL-001-sp_portal_runtime.sql` (PROPOSED). Só vira `approved/` após aprovação.
